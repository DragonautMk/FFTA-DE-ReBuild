## E509 European BIOS LZ77 caller census

The exact EUR ROM contains two aligned Thumb `SWI; BX LR` wrappers.
`08145254` selects WRAM LZ77 and has 19 direct Thumb BL patterns.
`08145250` selects VRAM LZ77 and has five. Protected Wine disassembly
`e509-eur-bios-lz77-roots-wine-do_1rw2s` verifies 17 instruction windows
covering the 24 patterns and both wrappers. Four previously recorded
clean-boot streams reproduce their exact bounds.

The source census checks 287 roots, including targets of aligned
ROM-mirror words with word-aligned type-10 headers and the boot controls.
Twelve roots decode to complete streams and nine are already owned in
`e316-d315`. Three have no owner and form the LZ77 bank called by one
VRAM initialization routine. In execution order:

- `08039d54` reads `08039dcc` and decodes `b4fa4c..b52764` to
  20,480 bytes at `06000000`.
- `08039d78` reads `08039dd8` and decodes `b52764..b5300e` to
  4,096 bytes at the destination in structure field `8c`.
- `08039d96` reads `08039ddc` and decodes `b53010..b536b6` to
  4,096 bytes at the destination in field `88`.

The three streams consume 15,464 bytes and yield 28,672 bytes. Stream
ends exclude padding. The literal for the neighboring source at
`b53740` is passed to a separate routine. The remaining register-fed
call sites, inherited and relative tables, ordinary use and deferred
platforms require separate evidence.

## E512 European halfword copy source banks

The original loop at `080369e8` reads and writes one halfword per
iteration. It adds the low 16 bits of the fourth argument to each
source word and the store preserves the low 16 bits of the sum.
The third argument supplies the halfword count. E512 authenticates
all 11 direct Thumb calls in the EUR ROM. The call immediately before
the E510 VRAM sequence uses this loop.

Nine calls load literal sources. They select six distinct spans of
22, 26, 30, 192 or 224 halfwords, with aliases at three roots. The
original language comparison at `08039cf6` selects `b53740` when the
stored language is 3 and `b53714` otherwise. Both spans contain 22
halfwords. The final plan derives bias `0x16a` for `0808edbe` from
its two setup instructions.

The other two calls load five-entry tables at `397d44` and `397d58`.
Both select a pointer using the stored language byte at `02001f6e`,
then add `60 * row` and read 30 halfwords. The two direct callers
of this selector supply row 0 or 1 by isolating bit six of an original
byte. All five language slots in each table therefore declare two
rows, or 120 source bytes per bank. Wider language values and
computed or indirect callers remain outside the verified domain.

`e512-eur-halfword-copy-callers-wine-he3iuspf` and the bank plan

(`d6b4c8..d8f308`, 147,008 bytes). The 25 maps occupy

## E606 European background-effect graphics at runtime

European `e356-d355` publishes `graphics.background-effect-graphics`
as `background-effect-graphics.bin`. The file concatenates five
authenticated ranges in manifest order. The first eight bytes hold
the directory and tile base pointers. The next 300 bytes are the
25 descriptors, followed by 147,008 bytes of packed 4-bit tiles and
30,000 bytes of little-endian tilemap entries.

Each 12-byte descriptor contains a relative tile offset, a tile byte
count and an absolute ROM tilemap pointer. Subtract the map bank's
ROM address, `08d8f308`, from that pointer to find the offset within
the tilemap section. Each map has 20 rows of 30 halfwords. The
original DMA queue reads those values with a 60-byte source stride
and a 64-byte VRAM stride.

The runtime binds the file only to the source ranges in its manifest.
The original task selects its descriptor and programs the tile and
map DMA jobs. Reads crossing a range boundary resolve each lane
through its corresponding resource or the original ROM. The e355
predecessor has its own authenticated resource layout.

Windows build `5nd_54ih` passes after updating the older dataset budget
test call. Wine `q0itfso_` runs one focused test on all 25 descriptors
with the 177,316 covered ROM bytes inverted in the managed machine.
The original queue executes 100 word DMA transfers and 500 halfword
rows. It copies all 177,008 payload bytes, preserves VRAM edges and row
padding, and matches the raw-ROM machine's complete state and guest
clock. The bank served 177,508 byte reads including descriptor and root
reads. The test passes 630 mixed-width reads across all three ROM
mirrors, and completes the original descriptor lookup prefix for
selectors 25 and 255. It attaches e355 and rejects both a relabeled e355

## Typed background packets

`gba_core::rom_data::bg_packets` decodes the next stage after LZ77. The caller
supplies separate destination, cumulative written-byte and packet budgets.
Parsing checks every read, alignment, counts, dictionary references and budgets
before allocating each packet. Repeated writes retain their original order;
this is a write program, not a replacement for mutable RAM. Terminal offsets
and consumed stream lengths are distinct from padding and dictionary bytes.

The halfword format begins with a destination byte offset and a byte count,
both little-endian u16, followed by literal u16 values. A dictionary variant
uses a u8 count and u8 indices into a separately supplied halfword dictionary.
Offset zero is valid for the first packet. A zero *next* offset terminates the
stream. Odd byte counts and misaligned/out-of-budget writes are refused.
The captured 456-byte body has 14 packets/196 values, consuming 450 bytes before
six padding bytes. Original USA 0801f098/EUR 08020208 apply it at EWRAM 7cb0.
The 1996-byte body has 112 packets/771 values, consuming 1992 bytes before four
padding bytes. Original USA 0801efb0/EUR 08020120 apply it at EWRAM d1a0,
through the original staged-pointer mechanism. These destinations are proven.
The [EUR map-loader classification](rom_data_maps.md) now ties the small plane
to the normal16×16height/flag grid; complete flag and alternate-context
semantics remain unclassified.

The paired-plane body has a u32 header. Bit 31 selects a dictionary at the
low-28-bit relative offset; bit 30 selects u16 indices instead of u8. Each
indexed packet has a u16 destination offset, u8 count and its indices. A clear
bit 15 in a dictionary halfword implies the pair `(value, value+1)`; a set bit
selects an explicit second halfword with both marker bits cleared. This yields
ordered u32 pairs. The captured 2960-byte body has 107 packets/770 pairs,
consumes 1867 stream bytes and references the dictionary at 1872. Its flags
select u16 indices; it writes into the combined calculated planes at EWRAM
91a0..d1a0. Original USA 0801ed24/EUR 0801fe94 give the same writes with unlimited

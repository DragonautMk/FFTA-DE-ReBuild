# FFTA DE-ReBuild 1.2.0 — draft release notes

This draft describes the changes being prepared since 1.1.2. The Android
preview has a new signing identity and installs alongside 1.1.2; migrate saved
progress as described below before considering removal of the earlier app.

## Desktop

- Manage extraction of supported game data from the System menu, with progress
  feedback and an optional preference to use verified extracted resources on
  the next launch. The original supported ROM is still required.
- Choose whether to create new automatic cartridge-save backups. Existing
  backups and restore controls remain available when the setting is disabled.
- Extend the opt-in European resource implementation and its bounded
  validation, including additional tilemap and compressed graphics data.

## Development and Android preview

- Make the ROM coverage report available on GitHub Pages and add a searchable
  treemap of identified data families. It is not a function-matching measure.
- Extend Debug Tools v2 integration evidence and improve local artifact
  retention and recovery workflows.
- Set the maintained Android preview to `1.2.0-android-preview.4`, version code
  31. The startup and pause menus show the installed version and build. It uses
  a new signing key and the application ID `com.fftarecomp.port.preview`;
  Android feature parity is incomplete.
- Open on the ROM-selection screen and import an exported cartridge save or
  save state there. Replacing a file requires confirmation and preserves a local
  recovery copy.

## Android migration from 1.1.2

The new preview is a **separate app**, not an in-place update of 1.1.2. The old
app and its data remain available. A one-time connected-computer ADB helper can
copy the cartridge save, states and backups after both apps are closed and use
the same ROM; it preserves both apps' previous saves locally. Settings do not
transfer. Android prevents the new app from reading the old app's private data
on its own. Export states from the old app or copy a save file to the device,
then choose the file under **Import previous saves** after selecting the same
ROM. Raw cartridge saves cannot identify their game, so choose the matching file.
Keep the old app and backups until the new progress is verified.
See the [detailed migration guide](https://github.com/DragonautMk/FFTA-DE-ReBuild/blob/main/AndroidPort/android/README.md#preview-migration-and-signing).

## Planned downloads

- **Windows x86-64**: `FFTARecomp-windows-portable.zip`
- **Linux x86-64**: `FFTARecomp-linux-portable.tar.gz`
- **Android ARM64**: `FFTARecomp-android-arm64-preview.apk`
- **Android migration helper**: `migrate_legacy_saves.py` (requires Python and ADB)

An original supported game ROM is required; provide a BIOS where the selected
configuration requires one. ROMs, saves and recordings are not included.

## Verification and remaining work

- The Windows cross-build passed 978 tests under Wine and two host tests; its
  portable ZIP passed integrity and executable-format checks, and the packaged
  command-line executable started under Wine. Native Windows has not been tested
  for this draft.
- The Linux build passed 979 tests; its portable archive passed integrity,
  executable-format and command-line startup checks.
- A host-side import check loaded the
  1.1.2 phone's three states and verified its normal cartridge-save bytes;
  original phone files were unchanged. The new APK was installed alongside
  1.1.2 on a moto g34 without changing those files. The one-time ADB migration
  then copied the cartridge, three states and two backups with verified hashes;
  the user reported the progress appeared present. Updating the preview to build
  29 preserved both apps' saves, and the user confirmed its menu label. Check
  your own transferred progress before removing an earlier app. Full gameplay
  remains unverified.
- The Android native core passed 45 tests (three fixture-dependent tests
  skipped), including import, confirmation and backup behavior. The build 31
  APK passed 31 Kotlin tests, matched the existing preview signing identity,
  and contained no private game data.

The Windows and Linux packages contain no files in their portable `Data`
directories. EUR resource coverage is incomplete and USA-specific resource
validation remains separate. Android feature parity remains incomplete.

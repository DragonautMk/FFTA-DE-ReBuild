# FFTA DE-ReBuild 1.1.1

This release brings the first set of desktop menu and gameplay features to the
Android preview. Android feature parity is still in progress.

## Android

- Open the in-game menu with the touch button above the directional pad. Menu
  panels show a scroll indicator when more options are available.
- Adjust screen profiles, brightness, grid strength, scaling mode, frame
  counters and menu transparency. Restart the current ROM from the menu.
- Save and load states in nine slots, with confirmation and one session undo.
  Import and export compatible Android and desktop states. The menu returns
  to gameplay after a successful save or load.
- Keep up to two verified cartridge-save backups and restore one from the menu.
  Fix a backup permission error that could stop a game from opening.

## Desktop and build tools

- Desktop can read compatible Android states and exchange state files with the
  Android preview.
- Docker builds reuse local toolchains and caches. The Linux scripts build
  Windows, Linux and Android packages, and the PowerShell launcher can build
  each platform or all three. Interactive build errors stay visible until
  acknowledged.

## Downloads

- **Windows x86-64**: `FFTARecomp-windows-portable.zip`
- **Linux x86-64**: `FFTARecomp-linux-portable.tar.gz`
- **Android ARM64**: `FFTARecomp-android-arm64-preview.apk`

An original supported game ROM is required. Provide your own BIOS where the
chosen configuration requires one. Game files and saves are not included.

The Android APK is a debug-signed preview. Its app version is
`1.1.1-android-preview` and its version code is 26. It uses the same signing
certificate as the previous published preview. The desktop packages retain
their existing internal Cargo version numbers.

Android still lacks some desktop menu, video and debug features, including
state-slot previews and temporal response. The state transfer, undo and backup
flows have automated synthetic coverage. Real-game transfer, undo and backup
restore on a phone remain unverified. Android uses one shared primary cartridge
save when switching ROMs. The Android and desktop cores can differ internally
after a replay even when the tested CPU, RAM, video and audio summaries match.

The desktop container builds passed their test gates, with the Windows tests
running under Wine. The Android APK passed its build and Kotlin unit tests. A
previous Android build was installed on a moto g34 5G, where the user confirmed
that a game opened. Native Windows testing and the remaining Android
real-game checks are outstanding.
